One event in.

SupplyChain Nexus is a multi-agent resilience workflow: deterministic tools compute every number, four Foundry specialist agents interpret those numbers for a human decision-maker, and an approval gate sits outside the model's authority entirely.

Grounded, not guessed

Every dollar figure, order count, and coverage day comes from a deterministic engine. Agents interpret facts; they never compute them.

5 live scenarios

The same pipeline runs correctly across five independently modeled suppliers, severities, and durations — not a single cherry-picked demo path.

Caught our own mistake

An early evaluation scored 0–40% because it was graded against a math benchmark, not this domain. We found it, rebuilt the evaluator, and re-ran it clean.

05 / 13

Why four agents
beat one generalist.

A single agent would have to reason about graph traversal, numerical simulation, contracts, procurement policy, and authorization inside one context window. That is exactly where ungrounded numbers and unclear ownership come from.

One generalist agent

Everything, one context

  • Numbers get calculated from memory, not tools — harder to catch a wrong figure
  • One oversized prompt mixes impact math, policy, and approval logic
  • No clear owner for a bad answer — is it the data, the reasoning, or the policy?
  • Hard to evaluate: one pass/fail score hides which responsibility actually failed
  • The model can reason its way past an approval boundary it shouldn't cross
Four specialists + one gate

Narrow objective, own tools

  • Separation of concerns — each agent has one question and one tool set
  • Grounding — decision-critical figures come back from deterministic tools, not the model
  • Testability — each specialist is evaluated independently against its own facts
  • Explainability — every stage emits its own input, output, and trace
  • Governance — the Recovery Planner can recommend; only the approval service can execute
06 / 13
Solution architecture

Four specialists.
One deterministic engine.
One human gate.

  1. Event received — the orchestrator validates the disruption event (supplier, duration) and opens a correlation trace.
  2. Impact Analyst calls the deterministic engine for revenue at risk, affected plants/materials, and inventory coverage.
  3. Simulation Strategist receives that impact package and compares five recovery strategies on cost, delay, and SLA risk.
  4. Recovery Planner receives the simulation results and justifies the recommended strategy with concrete next actions.
  5. Compliance Officer receives the recommended strategy and its cost, then states the required approval role.
  6. Human approval reviews the full evidence trail and approves or rejects — outside the model's authority entirely.

The bug we found
was in our own test,
not the agents.

An early Foundry evaluation run scored 0–40% across all five agents. The honest instinct was to assume the agents were broken.

Root cause: the evaluation was configured against the AIME 2025 math benchmark — a dataset with zero relation to supply-chain reasoning. The fix wasn't to accept the score, or hand-pick a flattering benchmark. We built local_agent_eval.py: a rubric evaluator that judges each specialist against the exact VERIFIED FACTS it received, checking rubric adherence and fabricated numbers. Re-run against real disruption scenarios, every agent passes consistently.

Relevance & groundedness

Numeric claims are checked verbatim against the facts block, not vibes.

Task adherence

Impact → comparison → recommendation → approval, in order, every time.

Policy adherence

Approval threshold and role logic hold even at $1.6B revenue exposure.
